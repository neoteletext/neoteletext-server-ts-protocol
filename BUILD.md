# Building neoteletext-server-ts-protocol

The source is TypeScript that Node runs as it is, by stripping its types
(Node 22.18 and later), so the tests run the source. A release is built:
Node strips no types from a package installed under `node_modules`, so a
consumer takes the JavaScript and declarations in `dist/`.

## What is needed

- **Node 22.18 or later.** `scripts/check.sh` refuses an older one.
- **TypeScript 7.0.2**, the latest release, and the quality tools (oxlint
  with oxlint-tsgolint, Prettier, Knip), all pinned in `package-lock.json`.
- **The protocol's types**, generated by the kit's own `scripts/types.ts`
  (Node's modules only; typescript.md TS-8 to TS-15) from the server's
  schema (`schema/protocol-15.json`, a copy of the server's
  `protocol/schema-15.json`) into `src/wire/generated/protocol.d.ts`, with
  the schema's structure beside it in `bytes.js`, by which the kit writes
  and reads bytes fields as base64. The generator maps each keyword of
  TS-9's table, a map whose names match one pattern (`patternProperties`,
  python.md PY-74), and fails, naming the keyword and its path, on
  anything else. A union's branches are named by their tag, one of `type`,
  `kind`, `event`, `form`, `packet`, `action` and `of`, and an untagged
  branch of several properties by the first it requires that no other
  branch has (PY-75). For protocol 15: an object of which exactly one of
  some properties is given (a `oneOf` of bare `required` lists, the
  amounts of page-rules.md RULE-106) is one type wherever the schema writes
  it inline, named by its properties as the Python kit names it (`Amount`
  for `plus` and a variable, the row or the firing; `TargetAmount` for
  `plus` and the row or the firing); a message with fields of its own of
  which exactly one of some optional ones is given (`regis` and `naplps`,
  `data` or `parts`: renderer parity PAR-21) is its object with those
  fields optional, which one is given being the validators' to hold; a
  union nested in a union joins it;
  and a group's `sound` command, which is no program message, is the union
  `RuleCommandSound` of `RuleCommandSoundPlay`, `…Stop` and `…Gain`.
  `scripts/validators.ts` turns off Ajv's one strict rule that refuses a
  `required` list beside its properties (`strictRequired`). The commit gate's step "the types, from the server's schema" runs
  it, then `node scripts/types.ts --check`, which generates again in memory
  and fails on the first line that differs.
- **Ajv 8**, pinned, at build only: `scripts/validators.ts` compiles the
  schema with Ajv's standalone mode into `src/wire/generated/`, one
  validator for each message by its `type` and one for each sound kind.
  The release ships those plain functions, with Ajv's two run-time helpers
  written in, so it needs nothing of Ajv when it runs.
- Nothing in `src/wire/generated/` is committed: every check and build
  makes it again, and Prettier and oxlint pass over it.
- **A new schema** from the server is taken in one commit by copying it
  over `schema/protocol-15.json`, naming the server's commit it is from in
  `scripts/check.sh` (`SCHEMA_FROM`), and changing what the regenerated
  types make fail to compile; the commit message names the server commit
  and what the schema changes for programs. The commit gate, and
  `scripts/check.sh schema`, fail when the copy differs from the server's
  `protocol/schema-15.json` at that commit, read from the server's
  repository at `~/devel/neoteletext-app-server` (or `NEOTELETEXT_SERVER`).
- **The shared files:** `kit-calls.tsv`, `test/fixtures/examples.jsonl`,
  `test/fixtures/rules-examples.jsonl`, `test/fixtures/timelines.jsonl` and
  `test/fixtures/command-lines.jsonl` and
  `test/fixtures/picture-examples.jsonl` are copies of neoteletext-common's
  `docs/audio/kit-calls.tsv`, `docs/audio/examples.jsonl`,
  `docs/rules-examples.jsonl`, `docs/timelines.jsonl`,
  `docs/command-lines.jsonl` and `docs/picture-examples.jsonl` at the commit `COMMON_FROM` names in
  `scripts/check.sh`; `scripts/check.sh shared` and the commit gate fail
  when any differs, read from `~/devel/neoteletext-common` (or
  `NEOTELETEXT_COMMON`). They hold this kit to the Python kit's calls and
  lines (typescript.md TS-2), to the rule tables of page-rules.md
  section 7.5 and RULE-93, the timelines of animation.md ANIM-19 and the
  commands of RULE-114 as both kits must write them (python.md PY-80), and
  to the picture builders' bytes (renderer-parity.md PAR-39, PAR-40).
- **The picture builders' limits:** `src/picture/regis-limits.ts` and
  `src/picture/naplps-limits.ts` are generated by
  `scripts/picture-limits.ts` from the ReGIS renderer's
  `crates/regis/src/limits.rs`, `palette.rs` and `surface.rs` and the
  NAPLPS renderer's `crates/naplps/src/limits.rs`, `surface.rs` and
  `crates/naplps-render/src/main.rs`, each constant by the renderer's own
  name, at the commits `REGIS_FROM` and `NAPLPS_FROM` name in
  `scripts/check.sh` (the ones the server pins), and committed.
  `scripts/check.sh picture_limits` and the commit gate generate them again
  from `~/devel/neoteletext-renderer-regis` and
  `~/devel/neoteletext-renderer-naplps` (or `NEOTELETEXT_REGIS` and
  `NEOTELETEXT_NAPLPS`) and fail when either differs (renderer parity
  PAR-39, PAR-40).
- **The rule table's limits:** `src/rules/limits.ts` is generated by
  `scripts/limits.ts` from the engine's
  `crates/neoteletext-rules/src/limits.rs`, the limits' one home
  (page-rules.md RULE-57, REQ-6608), at the commit `LIMITS_FROM` names in
  `scripts/check.sh` (the one the server pins), and committed, since the
  Linux host has no engine. `scripts/check.sh limits` and the commit gate
  generate it again from the engine's repository at
  `~/devel/neoteletext-renderer-teletext` (or `NEOTELETEXT_ENGINE`) and
  fail when it differs; a test compares it with the schema's bounds of a
  table, and fails on any other file that writes a limit's figure beside
  its name.

## Check

    scripts/check.sh stage    # the locked tools, the types and validators,
                              # the type check, formatting, lint and Knip,
                              # the tests
    scripts/check.sh schema   # the schema's copy against the server's
    scripts/check.sh shared   # the shared files' copies against neoteletext-common's
    scripts/check.sh limits   # the limits' copy against the engine's
    scripts/check.sh picture_limits  # the builders' limits against the renderers'
    scripts/check.sh build    # the release build into dist/

The git hooks (`git config core.hooksPath .githooks`) run `scripts/check.sh`;
`~/devel/neoteletext-common/DEVELOPMENT.md` section 9 says how the gates and the work branch `livedevelopment` work.
